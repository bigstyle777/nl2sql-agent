# few-shot 优化与去污染分析（2026-09-06）

## 优化动机

来自 `ATTRIBUTION-m5-final.md` 的归因：15 个失败中 8 个属于两个"套路缺失"簇——
两级类目穿越（6 题）、退款统计的日期字段选择（2 题）。这些是"本库本地惯例"层面的
知识，纯描述性提示词（M4）触顶，改用 few-shot 示例示范。

## 实现（src/agent/fewshot.py）

- 7 条黄金示例，覆盖：L2 类目聚合、L2→L1 穿越自连接、退款月度统计（refunded_at）、
  4 表 join 排名、宽表查询、状态 LOWER 归一、人均口径；
- 检索：字符 2-gram Jaccard 相似度（零依赖、确定性），取 top-2、阈值 0.15 以下不注入；
- 消融开关：`use_fewshot`（默认开启），评测 CLI `--no-fewshot`。

## 结果与数据泄漏自查

| 配置 | 执行准确率 | easy / medium / hard |
|---|---|---|
| m5-final（无 few-shot） | 87.5% | 98.3 / 90 / 50 |
| +few-shot（opt3-fewshot） | 97.5% | 100 / 100 / 85 |

97.5% 高得可疑：黄金示例是从失败 case 归因构建的，而失败 case 本来就是评测题，
部分评测题与示例问题高度相似（最高相似度 1.0），存在**数据泄漏**——模型可能是在
"背题"而非泛化。因此做了去污染分析：

- 按每题与示例库的最大 2-gram 相似度分组，阈值 0.35；
- **泄漏组（sim ≥ 0.35，14 题）**：无 few-shot 时 13/14 错，few-shot 后全对——
  这部分提升不能计入泛化能力；
- **无泄漏组（sim < 0.35，106 题）**：**94.3% → 100%**。

## 结论

- 在与示例无重叠的 106 题上，few-shot 依然带来 +5.7 个百分点的提升，收益是真实泛化；
- 泄漏组提升巨大恰说明示例正确击中了"套路缺失"根因，但对外汇报应以
  **去污染口径（94.3% → 100%，无泄漏子集）+ 全量口径（87.5% → 97.5%）并列**为准，
  单独引用 97.5% 而不说明泄漏自查属于夸大。

## 复现

```bash
python evals/run_eval.py --tag opt3-fewshot          # few-shot 开
python evals/run_eval.py --tag m5-final --no-fewshot # few-shot 关
# 去污染分组脚本见本文档相似度定义：src/agent/fewshot.py::similarity
```
