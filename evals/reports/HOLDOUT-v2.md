# 留出集 v2 单次终评报告（2026-09-06）

## 协议

40 题留出集（`holdout-v2.jsonl`）构建完成后**封存**：调参过程未参考其任何结果，
本报告为唯一一次评测，结果无论高低直接采用。构建脚本：`evals/build_holdout.py`。

留出集与主评测集（v1）的差异：
- 问法口语化、去模板化（"卖得最贵的商品标价多少？"式自然表达）；
- 覆盖 v1 未触碰的 SQL 特性：窗口函数（RANK / ROW_NUMBER / LAG）、CASE 条件聚合、
  字符串函数、双时间区间、连续活跃（gaps-and-islands）、相关子查询比率。

## 怎么解读 19 个点的差距

1. **99.2% 是"在内分布上的上限"，不是泛化能力**。主评测集的题目风格、SQL 特性
   与优化过程（提示词迭代、示例构建、口径修正）同源，系统被调到了这套题上。
2. **80.0% 是当前系统对"新问法 + 新特性"的真实泛化估计**。差距集中在 hard（50%）：
   窗口函数和复杂比率类是 few-shot 示例库没有覆盖的套路，模型退回 zero-shot 水平。
3. easy 100% 说明基础过滤/聚合能力稳定；medium 87.5% 说明部分新特性可被
   COLUMN_HINTS 与通用 SQL 能力覆盖。
4. 这不是坏消息：**没有一个公开的 NL2SQL 系统在分布外题目上不掉点**。
   有留出集，才第一次能"看见"掉点发生在哪（窗口函数、复杂比率），下一轮
   优化的方向从归因来，而不是从主集过拟合来。
